04 / Structure × runtime · the project's design contract

Immutable history. Recoverable work.

Structure · separate the concerns

Payload and governing metadata are distinct. An immutable artifact records what was admitted; a fold of events derives its status. A monthly mint bucket and a reader's optional time window are different concepts.

Runtime · protect the kernel

The gate and ledger preserve atomic admission. There is no transaction spanning ledger and operational store. A derived index can lag and catch up by replay; the ledger's fact history must remain intact.

Capture stops mid-import

Only committed envelopes have landed.

↓

Re-run capture

Idempotent admission avoids duplicates.

Derived indexes lag

The ledger holds the complete event stream.

↓

Replay to watermark W

Catch-up advances the derived state against the same ledger identity.

Mint stops after a file write

A valid artifact may lack its checkpoint row.

↓

Re-run mint

Content addressing makes the repeat file write harmless; the row can follow.

Re-ingesting sources can reconstruct their facts, but stamps new anam-times. Preserve the ledger to preserve the original learning history; authored operational records also need backup.
