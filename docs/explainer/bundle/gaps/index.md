# Gaps

* [A mint that fails after an importer batch is reported only in the daemon log](mint-failure-after-batch-only-logged.md) - After a declared ingest the mint's error lands on the operation as mint.error; after an importer batch mintOnRequest discards the result, and neither the response nor GET /v1/status carries it.
* [A weekly bucket width disables composed reads and incremental mints](weekly-width-disables-composed-reads.md) - The docs say weekly is also implemented; span.New accepts it, but a weekly id does not subdivide a year, so LayoutOf refuses it and every read and mint falls back to the full fold.
* [anam_submit's manifest does not declare current_versions](anam-submit-manifest-omits-current-versions.md) - The records importer emits payload.current_versions and anam_submit reads it, but the submit manifest's input_schema and consume list name only envelopes, definitions, batch and snapshot.
* [config.example.yaml is behind the config keys and names the wrong backup method](config-example-is-stale.md) - The example omits checkpoint_budget, backup_dir, backup_keep, max_read_bytes, server, zone and library_dir, repeats the stale operational-store list, and advises sqlite3 .backup while the daemon uses VACUUM INTO.
* [Definitions are registered on a 404, not at start](definitions-registered-on-404-not-at-start.md) - IMPORTERS §8.3 and §8.5 say an importer registers its Definitions every time it starts; a ductile plugin has no start, and anam_submit GETs each version on every batch and POSTs only when it is missing.
* [docs/API.md describes a conversational API that is mostly unbuilt](api-doc-is-a-design-not-the-code.md) - API.md (card 72) designs DescribeRecord, ListProjections, SubmitAssertion, CorrectAssertion and more as the contract for agents; the daemon's routes are the operator and importer ones in this bundle.
* [facet_index is written by catch-up but read by no read path](facet-index-written-not-read.md) - The schema comment says the timeline, type filter and bucket membership live here; the timeline in this tree composes from checkpoints or folds the ledger, and only anam changes reads the derived indexes.
* [Receipts pin the bundled Definition set only](receipts-do-not-pin-registered-definitions.md) - definition_set_version hashes the embedded manifests; a registered Definition that decides a snapshot's closing types is not in it, so a meds-style serve against a registered series rule that later changes verifies with no note.
* [Retract runs against the local files, never the daemon, and leaves the index behind](retract-runs-locally-only.md) - anam retract refuses a configured server and opens the files itself; there is no route or client method, so retracting the live record means stopping the daemon, and the operational index is behind until it starts again.
* [Sentences in ARCHITECTURE.md the code has moved past](architecture-doc-stale-sentences.md) - Zero-padded sort keys, RFC3339Nano times, only init and ingest open for writing, retract reads the full fold, commit returns admitted or rejected, and a ledger busy lock as a 503; each is one sentence behind a later card.
* [The anam-importers checkout is on card-58-one-off and behind its origin](importers-checkout-behind-origin.md) - The working tree is one commit ahead of a local master that is 12 commits behind origin/master; garmin, concept2 and the conformance tests exist only on origin/master, so this explainer cites what is tracked here.
* [The health-db worker is still built in after its source was retired](healthdb-worker-still-built-in.md) - Card 55 retired health-db in favour of the Garmin importer and tombstoned its facets, but internal/capture/healthdb, its ingest case, its scope entry and the example import remain in the binary.
* [The ledger has one secondary index](ledger-has-one-secondary-index.md) - §12 says the ledger carries no secondary indexes; every writable open creates anam_event_by_facet on (facet_id, seq) for the per-facet history the retraction check needs.
* [The storage table in ARCHITECTURE §8 lists things the code does not have](storage-table-in-architecture-is-stale.md) - VALUE#<hash> files, projection templates in SQLite, a receipt index, a span registry, saved bookmarks, sync cursors in use, GC state and an operational log are named; the code has checkpoint/sha256-<hex>.json files, embedded templates, receipts listed from the directory, and none of the rest.
* [token_scope is a dead table](token-scope-table-unused.md) - The operational store creates token_scope (source, type) for the gate's authenticated pillar; nothing reads or writes it. Importer scopes come from the importers file and the built-in workers' scopes from a Go map.
* [Whether writing an id field counts as composing identity is not settled](importers-write-identity-fields.md) - The contract says an importer composes no identity, and the gate does compose source_ref; but importers write the payload fields the identity pointers name: bp_csv's ordinal reading, garmin's id, the extractors' record ids.
