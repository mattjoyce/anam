A query is a Datalog program run over the [fold](/terms/fold.md) at a [watermark](/terms/watermark.md), through a [projection](/terms/projection.md). The projection decides which whole facets the query may see, as it does for a timeline; the query then relates them: joins across types along [fact-time](/terms/fact-time.md), selection by any payload field the served Definition's schema names, aggregates and windows. Its base relations are the [envelope](/terms/envelope.md) (`entry/7`, carrying `definition_version`, since a payload's shape is the shape of the version it was admitted under) and the payload fields read from the served copy (`attr/3`, for any pointer the schema defines). Bundled rules such as `current/2`, `displaced/2` and `linked/2` (the edges touching a facet, card 104) ship as a named, versioned rule set, and `current/2` is held equal to the [snapshot read](/terms/snapshot-read.md) by a standing test.

The answer is a derived value that hashes, with a [receipt](/terms/receipt.md) naming the watermark and ledger, the projection and its hash, the definition-set version, the rule-set hash and the query text, so `receipt verify` re-runs it. A query reads payload fields from the served copy and never from the store, moves no watermark and writes nothing; the evaluator is read-side and outside the [error kernel](/terms/error-kernel.md). Decided in [a read may select by payload; the store never does](/decisions/a-read-may-select-by-payload-the-store-never-does.md). Its surfaces are `anam query run` and `describe`, `POST /v1/query` for a program and `GET /v1/query` for the catalogue a program is written against; `docs/QUERY.md` is the reference and holds worked questions that a test runs against a real ledger. A query can also carry its projection in the request (card 211): `projection` takes a template object, with a manifest's knobs and no name or version, in place of a name. The projection loader checks it, a bad one is a 400 that names the field, and it is known by its content hash. The receipt marks it inline and the body is filed under that hash, so verify replays it after a restart. Every role may already read every projection, so it widens nothing. A query builds `attr/3` only when the relation it answers reaches it (card 203), so a program over the envelope alone pays nothing for the payloads.
